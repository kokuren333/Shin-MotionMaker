## 観点（危険度順）

1. **パスの安全**（MC-02、CL-11、CONTRACT M-2）：`--root` の外への逃げ道（`..`、絶対パス、ドライブレター、UNC、`\\?\`、大文字小文字、末尾のドット・空白、8.3 短縮名、ジャンクション、シンボリックリンク、ハードリンク、TOCTOU：検査後に差し替えられる経路）。`restrictToRoot`、`--allow-dir` の境界、`report_get` の許可リスト（MC-09、R-14）。実際に作業ツリー外の一時フォルダで試してよい（例 `<スクラッチ>\m2ar\`）。
2. **子プロセス**（CL-11、MC-03、R-5、R-6）：シェルを介していないか。argv のひな形どおりか。任意コマンドに化ける経路（オプション注入、`--` の扱い、`=` を含む値）。Windows の `.cmd`（npm）を `shell: true` で起動していないか。imagegen の事前拒否（`%`・`"`・改行）。
3. **run の生存期間**（MC-10〜14、TS-07）：切り離し、heartbeat、`lost` の判定、取り消しでプロセスツリーごと止まるか（Windows）、時間切れ、終端状態からの逆戻りがないか、`run.json` の書き込みが原子的か（壊れた JSON を読む経路）。
4. **排他**（MC-05、R-13）：ロックの取得が原子的か、古いロックの回収で二重実行にならないか、事前検査で失敗したとき run を作らないか（R-3）。
5. **結果の組み立て**（PH-03、CL-06、R-2、R-11、JT-12）：助言が `ok`・`verdict`・終了コードを変えないか。古い report を今回の結果として読まないか。0.4 のジョブ。
6. **project の書き込み**（MC-08）：`expect_sha256`、不変キー、一時ファイル＋rename、場面の内容を検査していないか（F5）。
7. **状態の導出**（§5.4、MC-07、F6、PH-05）：合否・スコア・順位の項目がないか、`hints` が助言か、状態をファイル以外に持っていないか。
8. **テスト**：TS-07 の各項目が実際に検証しているか（偽のスクリプトが本物の経路を通っているか）、`git` を起動していないか。

実行してよいもの：作業ツリー内の `npm ci`・`npm test`・`node tools/ci-local.mjs`、一時フォルダでの試行。
