### 2.2 PH-03（`advisory` と `gate`）

- **`advisory` は不合格・エラー・警告に見えない。** 金と赤を使っていない。三角も八角形も使っていない。状態系の6点（advisory・info・validate-ok・gate・warning・error）を並べると、最も軽く、最も淡い。PH-03 の「助言を不合格の見た目で表示しない」を、アイコンの側で満たしている。
- **`advisory` は「ゲートの一種」に見えない。** `gate` は支柱と縞の構造物で、`advisory` は柔らかい吹き出しなので、形の系統が違う。色も `gate` は trace-deep と白、`advisory` は trace-soft で、重さが違う。
- `advisory` と `info` はどちらも水色系だが、形（吹き出しと円）で区別できる。GU-05 では、ゲートと助言は区画の分け方でも区別する。変更は要らない（参考 S-2）。

### 2.3 様式4種の同格性（GU-07）

枠・白い面・図形の領域がそろっている点はよい。一方で、図形の重さと種類に偏りがある。各アイコンの内部（行・列 2〜13）で、白以外の画素を数えた結果：

| 様式 | 白以外の画素 | 図形 |
| --- | --- | --- |
| `style-biim` | 64 | 上下の帯（trace-deep）と中央の画面（trace） |
| `style-mixed` | 63 | 四角（trace-deep）と ink の輪郭付きの角丸の四角（trace） |
| `style-anime` | 48 | 大きな4方向の輝き（trace-deep） |
| `style-motion` | 29 | 小さな菱形2つ（trace-deep）と ink の 3px の連結 |

- `style-motion` の重さは他の約半分で、×1 では「白い枠に小さな点が2つ」にしか見えない。4つを並べたとき、motion だけが軽く、副次的に見える。
- `style-anime` の輝きと `style-motion` のキーフレームは、どちらも菱形・4方向の星の系統である。このため、×1 では anime と motion が「大きな星」と「小さな星2つ」に見え、同じ図形の大小の差になっている。
- 4方向の輝きは、UI では「新着・おすすめ・AI 生成」の印として広く使われている。4つの選択肢の中で1つだけがこの印を持つと、その選択肢が強調されているように見えるおそれがある。
- `style-biim` は最も重い。原典で `biim` は既定（ただし必須ではない）なので、既定の選択と重い見た目が重なると、「既定らしさ」が増す。

→ 必須 M-1。

### 2.4 CyberSprite の様式との整合

- 16×16、同じパレット番号と色、ink 1px の輪郭、14×14 の内容、アンチエイリアスなしは、§1 のとおり満たしている。
- 斜めの線は、45° か 2:1 の段で引かれている（`ghost-check` の柄、`mode-explainer` の脚、`style-motion` の連結）。
- 再利用アイコンと並べても、線の太さ・色の使い方・塗りの量に大きな違和感は無い。固有アイコンには 14×14 いっぱいの四角い枠（`app`・`cli`・`style-*`・`mode-explainer`）が多く、再利用アイコン（`add`・`remove`・`link`）より面が大きい。ただし、再利用の `folder` や `validate-ok` も同じくらいの面を持つので、許容の範囲内とみる。
- 角の処理がそろっていない。`app`・`style-*` は角を 1px 落としているが、`cli`・`mode-explainer` は直角である。再利用側にも両方の形があるので、参考 S-5 にとどめる。

### 2.5 由来と規則

- 再利用 13 点の原本は全件が無加工（§1）。PNG は画素一致の再書き出しである（S-6）。
- manifest の項目と NOTICE の要約は、GU-12 と DC-04 を満たす。追跡ファイルにローカルの絶対パスは無い。
- クリーンルーム：repo に参照画像は無い。固有アイコンの図形は一般的な慣習（吹き出し、端末のプロンプト、プラグ、八分音符、グラフ付きのイーゼル、ファスナー、幽霊のシルエット、虫眼鏡）で、特定の製品のアイコンやロゴを写したものには見えない。`mcp` は MCP の公式マークとは別の形である。`ghost-check` の幽霊は、目が2つの縦線、裾が波形の一般的な形で、既存のキャラクターに寄っていない。
- `tests/icons.test.ts` が、固有アイコンの制作者の名前を固定値で照合している。推奨 R-2。

## 3. 指摘

### 必須

**M-1 様式4種の重さと図形を、同格に見えるようにそろえる**（`style-anime`・`style-motion`。必要なら `style-biim`・`style-mixed`）

- 根拠：GU-07（MUST）「4つの様式モードを同格に並べる」。§2.3 の測定のとおり、`style-motion` は他の約半分の重さである。`style-anime` と `style-motion` は同じ菱形・星の図形の大小に見える。4方向の輝きは「新着・おすすめ・AI」の強調の印として読まれうる。どれもラベルで補えるが、4つの選択肢を並べる場面では、アイコンの重さと強調の印が「どれが主か」の手がかりになってしまう。
- 直し方の提案（形の決定は制作者に任せる）：
  1. `style-anime` から、4方向の輝き（菱形の星）をやめる。motion の図形と重ならず、一般的な強調の印でもない図形にする。たとえば、放射状の効果線（集中線）、または大きな瞳とハイライトを持つ顔の一部。ただし、再利用の `eye` と紛れないようにする。
  2. `style-motion` の重さを他の3つに近づける。たとえば、軌道を ink の 3px ではなく 2px 幅の trace か trace-deep の線にする。または、キーフレームを大きくし、軌道を枠の中で長く引く。
  3. 直した後に、4つを様式の選択欄と同じ順に ×1 と ×4 で並べたシートを作る。前の版を並べた1枚と、前の版のリビジョン番号も残す（CyberSprite §6.3）。画素数は確認の手がかりであって、合否のしきい値にはしない。

### 推奨

**R-1 `gate` を、×1 で旗ではなく遮断機（関門）に読める形にする**（`gate`）

- 根拠：支柱が行 3〜13 まで高く、縞の腕がその頂上に付いているため、×1 では市松模様の旗（ゴール・完了）に見える。GU-05 で「ゲート」の区画の見出しに使うと、「完了」と取り違えるおそれがある。
- 提案：支柱を低くする（例：行 7〜13）。腕は支柱の中ほどから右端（列 14）まで水平に伸ばす。支柱の左に短い重り、または腕の先に受け台を付けて、遮断機の形にする。縞の色は今の trace-deep と白のままにする（赤は状態アイコンだけに使う規則を守る）。

**R-2 TS-09 のテストで、制作者の名前を固定値で照合しない**（`tests/icons.test.ts:123`）

- 根拠：`assert.equal(icon.author, "Claude Opus 5.5", ...)` は、将来、別のモデルや人がアイコンを直したときに、記録を偽るかテストを書き換えるかを迫る。GU-12 が求めているのは制作者の記録であって、特定の名前ではない。
- 提案：固有アイコンについては、`author` が空でないことだけを表明する（再利用側と同じ）。

**R-3 改善の前後を並べた1枚を残す**（REPORT の D7、および今回の直し）

- 根拠：CyberSprite §6.3 の報告の規則「改善のたびに前後を並べた1枚を残し、前の版のリビジョン番号を書く」。D7 は自分で未達と記録している。
- 提案：M-1 と R-1 の直しでは、前後のシートを `docs/work/M5/` に置き、前の版のリビジョン番号を REPORT に書く。D7 の分は、前の画素が残っていないので、記録のままでよい。

### 5.2 M-1（様式4種の同格性、GU-07）— 解消

- **図形の重複が無くなった。** 4種の図形は「上下の帯と画面」「前髪と目の顔」「同じ四角が斜めに3段」「画面の斜めの2分割」で、系統がすべて違う。前回の問題だった菱形・星の大小関係は無い。
- **強調の印が無くなった。** 4方向の輝き（新着・おすすめ・AI の印）は消えた。4種とも同じ枠・白い面・10×10 の図形領域で、図形の色は trace-deep・trace・trace-soft だけ、ink を使う図形は無い。1つだけ目立つ手がかり（ink の輪郭、警告系の色、輝き）は見当たらない。
