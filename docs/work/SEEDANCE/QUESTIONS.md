## SEEDANCE-Q2 作成（POST）のリトライを発注より狭める

- 状態：**L2 判断（オーナー確認事項として報告）。**
- 発注 §3.2：リトライは 429・5xx・ネットワークエラーが対象。
- L2 の判断：取得・一覧・ダウンロードは発注どおり。作成（POST）は、送信後のタイムアウト・切断を「ネットワークエラー」でもリトライしない。サーバーがタスクを受け付けた後に応答だけ失われた場合、再送すると成功生成が2本になり二重課金になるため。送信前に失敗したと判定できる接続エラー（`ECONNREFUSED`・`ENOTFOUND`・`EAI_AGAIN`）と、429・5xx の応答はリトライする。リトライしなかった場合はレコードを `unknown` で残し、コンソールのタスク一覧で確かめるよう案内する。
- 理由：オーナーの最優先条件は「有料の呼び出しを意図せず起こさない」こと。リトライを狭めても安全側にしか倒れない。

## SEEDANCE-Q3 入力の扱いで発注に無い決めごと

- 状態：**L2 判断（設計メモ [DESIGN.md](DESIGN.md) に明記）。**
- 動画・音声のローカルファイル参照は v1 では受け付けない（API が URL または `asset://` を前提とするため）。画像のローカルファイルは Base64 の data URI で送る。
- 同じ shot_id の出力が既にあるときは `<shot_id>-2.mp4` のように番号を付け、課金済みの生成物を上書きしない（発注 §3.4 の `<shot_id>.mp4` は最初の1本の名前として維持）。
- キャッシュキーに backend（mock／ark）を含め、モックの結果が実 API のキャッシュとして返らないようにする。
- seedance-2-5 の 4K は単価が発注の表に無いため、見積りできないものとして作成を拒否する。
- 予算の判定は DRY_RUN でも同じ計算をする（モックの記録は費用 0 として数える）。
- （追記）Fable ゲートの軽微指摘により create に `force?: boolean` を足す（キャッシュを無視して作り直す。imagegen の `force` と同じ趣旨で、別テイクを作る創造側の自由度の確保）。
- （追記）Fable ゲートの重要指摘により、POST のリトライは 429・503 と送信前の接続エラーに限定し、500・502・504 は `unknown`（予算に予約したまま）とする。Q2 をさらに安全側に狭めたもの。
