## M8 に進むためにオーナーの判断が要ること（G4 §6 から）

1. **Q-01**：repo の作成と公開状態（推奨は public。Pages は M8 まで出さない）。
2. **main をリモートへ出す経路（G4 P-1）**：M0〜M7 はリモートが無いため L2 がローカルで main にマージした。そのまま push すると CI-05（同じコミットで PR の CI が成功したものだけを main に入れる）と衝突する。案：(a) リモートの main を初期コミットで作り、現在の履歴を別ブランチで push して PR の CI（ubuntu/24・windows/24・ubuntu/22 と Tier B）が成功してからマージする（推奨）／(b) オーナーが一度だけの例外を承認し、`VERIFICATION.md` に記録する。
3. **コミットの author メールアドレス**：全コミットの author・committer に個人のメールアドレスが入っている（原典 repo と同じ設定）。push すると公開される。noreply への切り替え（以後のコミット）と、既存履歴を書き換えるかどうか（AGENTS の「履歴を書き換えない」との兼ね合い）を公開前に決める。
4. 以上が決まったあと、L2 が M8 を発注する：リモート CI の実行証拠（ubuntu の TS-07・MC-02・CL-11・TS-04、Node 22）、Pages の初回デプロイ（手動）、`verify-pages` の実公開 URL での実行、CI-08 の4条件の記録、版のタグ。
